# 3. 管理経路とrootアクセス

## 管理IPと個体識別の変遷

記録群にはT6A `192.168.3.2`、T6B `192.168.3.247`、補助管理用として扱われた `192.168.3.1` が現れる。後日のT6A単独STA管理候補は `192.168.3.13`。これらは異なる日時・network modeの値であり、`.1`の個体やA/B対応をIPだけで決めない。特に後日のSTA管理IPをEasyMesh BH側のIPとして扱わない。A/B対応はhostname、物理配線、MACをローカルの秘匿資料で照合した。

## 2026-08-23前後の手段

T6Aは先行してroot SSHを利用でき、T6BはWeb UIの入力処理を介したコマンド実行が確認された後、Dropbear/SSHを開通させる作業が行われた。BからのHTTP取得確認を誤認しないよう、HTTPサーバ側の接続元IPを確認する診断も計画・実施された。BのSSHを用意した主目的は、二台の設定・ログ採取・復旧を独立して行えるようにすることだった。

**公開しないもの:** RCE実装、Web UI資格情報、SSH鍵、投入スクリプト、外部管理経路の内部情報。以前のプロンプトや作業ディレクトリにそれらが含まれるため、原文引用は避けた。

## 再現前に満たす条件

1. 本体ラベルや実機情報を使い、A/BをMAC・hostname・接続経路と合わせて識別する。
2. 変更前のネットワーク、EasyMesh、wireless、Dropbear設定を安全な場所へ保全する。
3. 通常のLAN経路に加え、別経路の復旧方法を用意する。
4. 変更後は管理SSHが失敗してもMesh状態を別のコンソール/機器から観測できるよう準備する。

当時のroot取得方法の詳細な再現は、未公開の安全条件・個体固有情報を含み、ここでは手順化していない。
