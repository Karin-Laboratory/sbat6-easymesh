# 22. 5ch投稿866〜868への回答

## そのまま投稿できる短い返信

SBAT6 2台のEasyMesh親子化は実機で成功記録があります。まず6 GHz単独BHでController距離0 / Agent距離1、6G backhaul、ケーブルを抜いた後の接続維持、端末間iperf3約350/330 Mbpsを確認し、その後5+6 GHzの2-link MLOも成立したと当時の記事に記録しています。MLOではSAE/PMF不一致によるRSNE mismatchを直し、再起動後の復帰と約0.91〜0.94 Gbpsも報告しています。

SSHが切れる原因は、Dropbear停止だけでなくfirewall reload、interface/IP変更、UCI書換え、rebootを分けて見る必要があります。保存ファーム解析ではinterface hotplug/WAN再構成からfirewall reloadする経路がありましたが、個別切断を起こした実行主体までは確定していません。まず本リポジトリの[read-only診断](20-ssh-loss-troubleshooting.md)を行い、実機固有の設定を確認してください。root passwordの再起動後永続性は未検証です。

詳しい記録: [root取得後からEasyMeshまで](21-from-root-to-easymesh.md)

## Q1. KnOSがiptablesを元に戻すのはなぜ？

手動iptables ruleはruntime tableにだけ入るため、OpenWrt firewall serviceがreloadするとUCI/firewall includeからtableを再構築します。保存Bank Bにはiface hotplugの`20-firewall`、`ql_wwan_config.sh`内のreload、`ql_lan_config.sh`のfirewall UCI更新/reloadがありました。どれが投稿者の時点で発火したかは不明です。`knos_uci_revert.sh`の存在だけを原因と断定できません。

## Q2. rc.localでSSHを起動するだけではなぜ駄目？

`rc.local`からdaemonを起動してもprocd管理、network bind、firewall許可の永続性は別です。interface再構成はfirewall reloadやDropbear network triggerを起こし得ます。先にOpenSSHかDropbearかを特定し、listener、procd、UCI、runtime firewall、IP/uptimeを分けて診断します。

## Q3. SSHとiptablesを再起動後も維持するには？

基本はdaemonをprocd/UCIで管理し、firewallの永続設定層に許可を置いて、実機固有のKnOS上書きを確認することです。過去T6Aでは`/data`上のseedを`/data/sysupgrade.tgz`経由でoverlayへ戻す独自復旧方式があり、cron/watchdogとともにSSH鍵アクセスを2回の再起動後に復帰させた記録があります。これは特定の過去構成での復旧実績であり、一般向けの万能手順ではありません。実機変更可能な別管理経路と復旧手段なしに適用しないでください。

## Q4. root passwordは固定化できる？

理論上は`/etc/shadow`とoverlay/起動復元を確認すべきですが、この記録にはroot passwordを変更して再起動後に認証成功した証拠がありません。Dropbear `-s -g`ではpassword loginを禁止し、復旧は鍵認証でした。よって鍵SSH復帰とpassword永続化は別で、後者は未検証です。password/hash/private keyは公開しないでください。

## Q5. SBAT6を2台でMesh親子化できる？

できます。本人公開記事の実測記録ではT6A Controller (`DeviceRole=1`)とT6B Agent (`DeviceRole=2`)、双方`MapMode=1`、有線onboarding後に6 GHz単独BH。Controller distance 0、Agent distance 1、6G medium、Agent BH status 1/type 4、抜線後の6 GHz APCLI維持を確認しています。さらに5+6 GHz MLO成立、再起動後復帰、Ethernet端末iperf3約0.91〜0.94 Gbpsも報告されています。詳細は[EasyMesh章](08-wireless-backhaul.md)、[MLO章](10-mlo.md)。

## Q6. 同じことを試すなら何から始めればいい？

変更せず、uptime/IP、実daemonとlisten port、procd状態、firewall runtimeとUCI設定hash、直近ログを記録してください。次に別経路でMesh topologyとAgent管理IPを確認し、IPv4管理喪失とMesh脱落を分けます。再現順序と危険条件は[実践ガイド](21-from-root-to-easymesh.md)にあります。
